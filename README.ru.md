# ZCode для bb

Запускайте установленный агент ZCode внутри [bb](https://getbb.app) с
индивидуальным Coding Plan Z.ai: файлы, терминал, нативные навыки и команды.
[English](README.md).

Ранний неофициальный плагин, не связанный с Z.ai, ZCode или bb. Запросы к модели
отправляет установленный ZCode; bridge обращается к Z.ai за краткоживущими
токенами проекта для общего входа Desktop. Соответствие использования
условиям Coding Plan — ваша ответственность. Версия в этом дереве — `v0.1.1`.
См. [примечания к версии](RELEASE_NOTES.md) и
[опубликованные выпуски](https://github.com/emlevsky777/bb-plugin-zcode/releases).

Пользователям ZCode Desktop 3.16.3 рекомендуется обновиться до v0.1.1:
его OAuth-семантика соответствует этой версии Desktop. Поддержка Desktop
3.15.1 сохранена.
Исходный репозиторий публичный.

## Требования и установка

macOS на Apple silicon, bb 0.47.1 или новее, установленный ZCode Desktop, Git
(Xcode Command Line Tools) и вход с индивидуальным Coding Plan. Host Node и сборщик предоставляет
bb; Python, Homebrew и глобальный npm не нужны.

В bb откройте **Settings → Installed plugins** (Plugins), затем
**New plugin options → Install from source** и вставьте:

```text
git:https://github.com/emlevsky777/bb-plugin-zcode.git@^0.1.0
```

Просмотрите и подтвердите установку. Источник выбирает стабильные версии
в диапазоне `^0.1.0`. Та же установка доступна в терминале bb:

```sh
bb plugin install git:https://github.com/emlevsky777/bb-plugin-zcode.git@^0.1.0
```

bb собирает server и host. ID плагина — `zcode`. Откройте тред, выберите
**ZCode**, модель (GLM-5.3, если доступна), разрешения **Full**, отправьте сообщение.
Разрешения bb определяют доступ инструментов; учитывайте команды и доверие к проекту.

Первый вход в индивидуальный Z.ai Coding Plan выполните в ZCode Desktop.
Оставьте **ZCode sign-in source** в режиме `desktop` (по умолчанию).
Плагин читает общий вход и обновляет краткоживущие токены проекта в памяти,
но не обновляет сохранённый OAuth/business-токен. Если сервер отклонил его,
откройте Desktop и войдите заново, затем повторите запрос в bb. Простой запуск
Desktop не проверен как способ автоматического обновления токена. Срок жизни
и реальное истечение сохранённого токена не измерены; отказ и восстановление
проверяются офлайн. Следующий запрос читает изменившийся вход без перезапуска
bb. Команда `zcode` в PATH не нужна. Переименованные приложения находятся через
Spotlight; резервный поиск — `/Applications` и `~/Applications`. При нескольких
копиях предпочтение отдаётся системному Applications.

Перед обновлением или удалением остановите каждый тред ZCode кнопкой **Stop**.
Откройте **Settings → Installed plugins → ZCode**, просмотрите и примените
предлагаемое обновление. Удаление — **ZCode actions → Remove from bb**.
Обновления следуют источнику установки и стабильному диапазону. Точные теги и commits закреплены; смена
источника требует удаления и новой установки. В bb 0.47.1 удаление сбрасывает
настройки, secrets и расписания, а данные сессий плагина остаются.

Вариант через CLI: в правой панели треда bb выберите **Open new tab → Start terminal**.
В нём bb предоставляет CLI; команда `bb` в системном Terminal не нужна:

```sh
bb plugin outdated
bb plugin update zcode --yes
bb plugin remove zcode
```

Удаление убирает регистрацию, настройки, secrets и расписания плагина.
bb 0.47.1 удаляет неиспользуемые managed Git artifacts; данные плагина и загруженные
host artifacts могут остаться. При стандартном каталоге данных bb проверяются:

- `~/.bb/plugins/cache/git/github.com/emlevsky777/bb-plugin-zcode/<commit>/`
  — checkout и собранные бандлы установленного commit.
- `~/.bb/plugins/zcode/` — данные плагина, включая `host-data/` и `bridge-data/`.
- `~/.bb/plugin-host-artifacts/zcode/` — загруженные host-бандлы.

Для необязательной полной очистки скопируйте точный путь **Source** со страницы
плагина **до** удаления. В терминале bb `bb status --json` показывает `dataDir`;
если это не `~/.bb`, замените каталог в путях ниже. Остановите все треды ZCode,
включая фоновую работу, затем выберите **Remove from bb**.
Только после этого вручную удалите точные оставшиеся каталоги:

```sh
# Замените <commit> на ID checkout, записанный до удаления.
rm -r -- "$HOME/.bb/plugins/cache/git/github.com/emlevsky777/bb-plugin-zcode/<commit>"
rm -r -- "$HOME/.bb/plugins/zcode"
rm -r -- "$HOME/.bb/plugin-host-artifacts/zcode"
```

Удаляйте checkout, только если его не использует другой установленный плагин;
не удаляйте весь Git-кэш bb. Ручная очистка данных удаляет локальные данные
сессий плагина и кэши, поэтому эти нативные сессии больше нельзя продолжить.
Ни удаление плагина, ни эта очистка не затрагивают вход и историю ZCode Desktop
или историю тредов bb. Сохраните нужные настройки заранее; секретные значения
нельзя переносить в чат или issue.

## Возможности и пределы

- Каталог моделей аккаунта и поддерживаемые уровни рассуждения. Исчезнувшая явно
  выбранная модель или уровень дают ошибку без подмены.
- Продолжение тредов, остановка основной работы, сжатие контекста,
  указания во время хода, субагенты при включённой настройке bb.
- Нативные навыки ZCode и навыки, доступные только bb. Выбор навыка/команды
  через меню на базе этого выпуска не проверен вживую. Реализация принимает
  одну нативную команду на сообщение; для нового резидентного навыка может
  потребоваться новый тред.
- Append-инструкции bb и навыки, доступные только bb, доставляются один раз
  на native-сессию, включая холодное возобновление. Метаданные содержат точные
  пути `SKILL.md`; bb-only навыки читаются файловым инструментом и не регистрируются
  в native Skill. Уже обнаруженные native канонические файлы и имена исключаются.
  Обновления инструкций/корней навыков применяются к новой сессии без пересоздания
  текущей. Замена системных инструкций не поддерживается.
- PNG/JPEG/GIF/WebP до 10 MiB, inline-изображения, UTF-8 файлы до 256 KiB.
  PDF, бинарные файлы и удалённые URL изображений отклоняются.
  Чтение изображения зависит от native-модели: в проверенной комбинации
  GLM-5.3-Flash переписал приложенную таблицу без инструментов, а GLM-5.3 сообщил,
  что видит только её путь, и в bb, и в ZCode Desktop. Прямое восприятие картинки
  GLM-5.3 не установлено; сам приём вложения этого не доказывает.
  Проверенный результат GLM-5.3 с инструментами получен через native Read,
  затем анализатор изображений ZCode.
  В планах, пока недоступно: PDF-вложения, большие текстовые файлы и другие
  форматы. Сроки не обещаются.
- Настоящий HOME и общее хранилище ZCode Desktop: личные/проектные инструкции,
  отдельные навыки, включённые нативные плагины и настроенные MCP-серверы.
  У bb отдельны база сессий и история и журналы. `ZCODE_DATA_BASE_DIR` не задаётся:
  native ZCode использует каталог входа Desktop `~/.zcode/v2` напрямую и может
  обновлять токены, как процессы Desktop. Сам плагин не пишет
  `~/.zcode/cli/config.json` и настройки Desktop.
- Память следует boolean из `~/.zcode/v2/setting.json` Desktop. Если значение
  отсутствует, невалидно или недоступно, действует **ZCode memory fallback**
  (по умолчанию ON). Память и субагенты меняются на следующем обычном ходе;
  steer сохраняет активные настройки. Другие runtime-настройки Desktop не перенимаются.

После успешного сжатия следующий обычный ход проверяет активную native-историю
и один раз восстанавливает исходный блок bb, если прежняя копия свёрнута.
При автоматическом сжатии native может отправить внутренний запрос до этого
шага; остаток этого хода может идти без полного блока bb. Непрерывное сохранение
инструкций и навыков внутри такого хода не поддерживается.
Проверка Г4 показала: native guide возвращает блок во второй запрос, если перед
ним нет пользовательского guide, и лишь в третий, если пользовательский guide
уже ожидает доставки. Модель также отвечает на служебный блок видимым сообщением.
Поэтому автоматическая повторная доставка через guide не включена.
Собственного предела 64 КиБ для инструкций и файлов навыков нет; указанные выше
пределы вложений относятся только к загруженным вложениям.

MCP-конфигурация загружается при создании сессии. После добавления сервера в
Desktop создайте новый тред bb либо остановите и холодно продолжите существующий.
Первый OAuth-вход в MCP выполните в Desktop; его запуск внутри bb не установлен.
Сбой отдельного сервера остаётся в диагностике и `bb zcode-report`, без
предупреждения в разговоре и блокировки обычного ввода. Hooks подчиняются
нативным правилам включения и доверия; настроенного hook для live B-2 не было.
Точность нативных denylist-patterns не гарантируется: `Bash(echo:*)` исключал
весь Bash, а `Agent*` не исключал Agent.

Указания в очереди ZCode могут потеряться при разрыве или продолжении, повтора нет.
Они сохраняют модель, рассуждение, режим входа, память и субагентов активного хода; новые настройки
действуют со следующего обычного хода. Отправка с неизвестным исходом автоматически
не повторяется. Перед повтором проверьте тред. Ошибки сервиса показывают причину/код;
проверьте ожидающий повтор bb перед новой отправкой. Холодное продолжение и
восстановление используют сохранённую native-сессию; неизвестный исход ввода
сначала выясняется, без слепого повтора. `bb zcode-report` даёт диагностическую
сводку, которой можно поделиться.

Необязательный **Backup Coding Plan key** вводится только в защищённую настройку.
Явно выберите `coding-plan-key`; автоматического перехода с входа через Desktop или на
pay-as-you-go API нет. Изменённый источник применяется к следующему обычному
вводу; активная работа и уточнения сохраняют свой выбранный источник.
Серверный учёт квоты для режима ключа не установлен.

## Границы доверия

Плагины bb исполняются с полным доверием и доступом вашей учётной записи на сервере
и хосте. Перед включением изучите репозиторий и установленный ZCode. Провайдер
запускает CLI через Helper; ZCode управляет запросами к моделям, инструментами
и сетью. Содержимое проекта и запросы могут уходить через ZCode, как при прямом
использовании. Отдельного модельного endpoint или загрузки отчётов плагин не добавляет.

Плагин читает общий вход ZCode; native ZCode может обновлять токены.
Для OAuth-входа bridge получает native project access token в памяти через
API учётной записи Z.ai; credentials и пользовательскую конфигурацию он не пишет.
У сессий bb отдельные данные/история,
они не появляются в Desktop. Плагин записывает привязки сессий, нативные данные,
кэши и диагностику в каталог данных bb. Builtin и personal provider config
выбирает сам ZCode по месту; плагин не хранит их копии. App-server по-прежнему
нужны host account overlay и runtime headers, как в Desktop. Карточки фоновых
задач и checkpoint сохраняют полную native-команду с аргументами. Неподтверждённый
ввод отмечается без повторной отправки и без убийства native-процесса по таймеру
подтверждения; перед повтором нужно выяснить исход.
Исходные личные/проектные настройки и навыки читаются по месту. Нативные плагины
могут запускать hooks и в Desktop, и в bb; включение расширяет круг доверенного
кода. Нативные инструменты имеют полный доступ к настоящему HOME и окружению.

Observer неактивен без явной настройки собственного loopback proxy и сертификата.
Локальные отчёты исключают запросы, содержимое проектов и значения credentials.
Журналы ротируются, но у истории и кэшей хоста нет жёсткого общего лимита.
Не публикуйте каталог данных, сырые журналы, credentials или ссылки авторизации.

## Сообщить о проблеме

В правой панели треда bb выберите **Open new tab → Start terminal** и выполните
`bb zcode-report` (текст), `bb zcode-report --json` или `bb zcode-report --help`.
В этом терминале bb предоставляет CLI; системный PATH настраивать не нужно.
Отчёт **server-local**: он описывает установку и события на сервере bb, а не
удалённый host агента или каталог вызывающего терминала. Личные пути и содержимое
сессий исключены. Наличие файла credentials не доказывает готовность входа;
она не проверяется. Коды выхода: 0 — успех/help, 1 — ошибка сбора,
2 — неверные аргументы; JSON ошибок: `{ok:false,error:{code,message}}`.
При help и неверных аргументах данные не собираются.
Приложите просмотренный вывод к
[GitHub issue](https://github.com/emlevsky777/bb-plugin-zcode/issues), указав шаги,
время/часовой пояс и точную ошибку. Команда ничего не загружает. При нескольких
установках используйте `bb plugin run zcode`. Журналы: `bb plugin logs zcode`.

## Разработка и лицензия

На поддерживаемом host Node: `npm ci`, `npm run typecheck`, `npm test`.
`bb plugin build` создаёт server и host artifacts. Тесты офлайн с синтетическими
fixtures, квоту Coding Plan не расходуют.
