# ZCode Provider для bb

Запускайте установленный агент ZCode внутри [bb](https://getbb.app) с
индивидуальным Coding Plan Z.ai: файлы, терминал, нативные навыки и команды.
[English](README.md).

Список моделей следует каталогу аккаунта Desktop, включая GLM-5.4, когда
она доступна. Модели Start Plan появляются рядом с моделями Coding Plan
при наличии доступа.

Последний релиз с тегом **v0.2.4**. [Примечания к релизам](RELEASE_NOTES.md) ·
[Опубликованные выпуски](https://github.com/emlevsky777/bb-plugin-zcode/releases)

Это неофициальный плагин, не связанный с Z.ai, ZCode или bb. Используйте его
в соответствии с условиями Coding Plan.

## Требования и установка

macOS на Apple silicon, bb 0.47.1 или новее, установленный ZCode Desktop, Git
(Xcode Command Line Tools) и вход с индивидуальным Coding Plan. Host Node и сборщик предоставляет
bb; Python, Homebrew и глобальный npm не нужны.

В bb откройте **Settings → Installed plugins** (Plugins), затем
**New plugin options → Install from source** и вставьте:

```text
git:https://github.com/emlevsky777/bb-plugin-zcode.git@main
```

Просмотрите и подтвердите установку. Источник отслеживает публичную ветку
`main`. Та же установка доступна в терминале bb:

```sh
bb plugin install git:https://github.com/emlevsky777/bb-plugin-zcode.git@main
```

Войдите в индивидуальный Z.ai Coding Plan в ZCode Desktop. В bb оставьте
**ZCode sign-in source** в режиме `desktop` (по умолчанию). Откройте новый
тред, выберите **ZCode Provider** (`zcode-provider`), GLM-5.4 при её наличии
или другую модель из своего каталога и разрешения **Full**.
bb находит ZCode Desktop на Mac, поэтому команда `zcode` в PATH не нужна.

**Первое подключение.** macOS может запросить пароль от Mac в системном окне
Keychain. Это даёт bb доступ к ключу, который защищает существующий вход
в ZCode Desktop. Если Z.ai отклонит сохранённый вход, войдите заново в Desktop
и повторите запрос в bb. Следующий запрос прочитает обновлённый вход.

При переходе с нашей линии v0.1.x установите плагин заново из этого источника
и создайте новый тред. [Подробности перехода](RELEASE_NOTES.md#distinct-identity-and-fresh-installation).

В начале каждого нового треда ZCode Provider, до первого ответа модели, одно
уведомление объединяет предупреждение о совместимости и доступном обновлении
плагина. Если BB или ZCode Desktop новее проверенной версии, оно называет
установленную и проверенную версии. Сведения об обновлении берутся из сохранённых
результатов BB по потребности, не чаще раза в час для всех хостов этой установки.
Следующие промпты и
возобновление треда не повторяют уведомление; обновление, обнаруженное позже,
дождётся нового треда. Недоступность сведений не мешает обработке промпта.

Перед обновлением или удалением остановите каждый тред ZCode кнопкой **Stop**.
Откройте **Settings → Installed plugins → ZCode Provider**, просмотрите и примените
предлагаемое обновление. Если установка отслеживает `main`, BB применит
последний коммит этой ветки. Удаление — **ZCode Provider actions → Remove from bb**.

Установленные копии с источником `^0.2.0` продолжают отслеживать теги релизов.
Чтобы перейти на `main`, удалите плагин и установите его заново из источника
выше. При удалении сбрасываются настройки, секреты и расписания плагина.

Вариант через CLI: в правой панели треда bb выберите **Open new tab → Start terminal**.
В нём bb предоставляет CLI; команда `bb` в системном Terminal не нужна:

```sh
bb plugin outdated
bb plugin update zcode-provider --yes
bb plugin remove zcode-provider
```

Локальные данные плагина могут остаться после удаления.
[Инструкция по ручной очистке для v0.2.4](https://github.com/emlevsky777/bb-plugin-zcode/blob/v0.2.4/README.ru.md#L108-L135).

## Возможности и пределы

- Каталог моделей аккаунта и поддерживаемые уровни рассуждения. Исчезнувшая явно
  выбранная модель или уровень дают ошибку без подмены.
- Продолжение тредов, остановка основной работы, сжатие контекста,
  указания во время хода, субагенты при включённой настройке bb.
- Нативные навыки ZCode и навыки, доступные только bb. Выбор навыка/команды
  через меню на базе этого выпуска не проверен вживую. Реализация принимает
  одну нативную команду на сообщение; для нового резидентного навыка может
  потребоваться новый тред.
- Append-инструкции bb и навыки, доступные только bb, доставляются один раз
  на native-сессию, включая холодное возобновление. Метаданные содержат точные
  пути `SKILL.md`; bb-only навыки читаются файловым инструментом и не регистрируются
  в native Skill. Уже обнаруженные native канонические файлы и имена исключаются.
  Обновления инструкций/корней навыков применяются к новой сессии без пересоздания
  текущей. Замена системных инструкций не поддерживается.
- PNG/JPEG/GIF/WebP до 10 MiB, inline-изображения, UTF-8 файлы до 256 KiB.
  PDF, бинарные файлы и удалённые URL изображений отклоняются.
  Чтение изображения зависит от модели. Некоторые модели используют для этого
  инструмент анализа изображений ZCode.
- Настоящий HOME и общее хранилище ZCode Desktop: личные/проектные инструкции,
  отдельные навыки, включённые нативные плагины и настроенные MCP-серверы.
  У bb отдельны база сессий и история и журналы. `ZCODE_DATA_BASE_DIR` не задаётся:
  native ZCode использует каталог входа Desktop `~/.zcode/v2` напрямую и может
  обновлять токены, как процессы Desktop. Сам плагин не пишет
  `~/.zcode/cli/config.json` и настройки Desktop.
- Память следует boolean из `~/.zcode/v2/setting.json` Desktop. Если значение
  отсутствует, невалидно или недоступно, действует **ZCode memory fallback**
  (по умолчанию ON). Память и субагенты меняются на следующем обычном ходе;
  steer сохраняет активные настройки. Другие runtime-настройки Desktop не перенимаются.

После успешного сжатия следующий обычный ход проверяет активную native-историю
и один раз восстанавливает исходный блок bb, если прежняя копия свёрнута.
При автоматическом сжатии native может отправить внутренний запрос до этого
шага; остаток этого хода может идти без полного блока bb. Непрерывное сохранение
инструкций и навыков внутри такого хода не поддерживается.

Штатный индикатор bb показывает оценку занятого контекста и ёмкость выбранной
модели. Он обновляется, когда ZCode сообщает данные учёта. При холодном
продолжении показание восстанавливается. После сжатия индикатор ждёт данных
следующего основного запроса.

Инструменты плагинов BB доступны ZCode через локальный MCP endpoint сессии.
Если плагин не может прочитать конфигурацию MCP, он сохраняет нативную
конфигурацию и объясняет, почему инструменты BB недоступны. При холодном
продолжении endpoint создаётся заново. Уточнения сохраняют каталог
инструментов. Остановка или разрыв соединения отменяет ожидающие вызовы без повтора.

Endpoint слушает `127.0.0.1` без токена. Другие локальные процессы могут
вызывать инструменты в контексте треда. Запросы с `Origin` отклоняются.
Передача инструментов BB нативным субагентам и восприятие изображений
через эти инструменты пока не проверены.

MCP-конфигурация загружается при создании сессии. После добавления сервера в
Desktop создайте новый тред bb либо остановите и холодно продолжите существующий.
Первый OAuth-вход в MCP выполните в Desktop; его запуск внутри bb не установлен.
Сбой отдельного сервера остаётся в диагностике и `bb zcode-provider-report`, без
предупреждения в разговоре и блокировки обычного ввода. Hooks подчиняются
правилам включения и доверия ZCode. Их работа в живых сценариях пока не проверена.
Исключения действуют на уровне инструмента целиком.

Указания в очереди ZCode могут потеряться при разрыве или продолжении, повтора нет.
Они сохраняют модель, рассуждение, режим входа, память и субагентов активного хода; новые настройки
действуют со следующего обычного хода. Отправка с неизвестным исходом автоматически
не повторяется. Перед повтором проверьте тред. Ошибки сервиса показывают причину/код;
проверьте ожидающий повтор bb перед новой отправкой. Холодное продолжение и
восстановление используют сохранённую native-сессию; неизвестный исход ввода
сначала выясняется, без слепого повтора. `bb zcode-provider-report` даёт диагностическую
сводку, которой можно поделиться.

Необязательный **Backup Coding Plan key** вводится только в защищённую настройку.
Явно выберите `coding-plan-key`; автоматического перехода с входа через Desktop или на
pay-as-you-go API нет. Изменённый источник применяется к следующему обычному
вводу; активная работа и уточнения сохраняют свой выбранный источник.
Серверный учёт квоты для режима ключа не установлен.

Доступные модели, например
**GLM-5.3-Flash · Start Plan**, появляются рядом с Coding Plan под отдельными
bb-ID (`start-plan/GLM-5.3-Flash`). Выбирайте модель в каждом треде; общей
настройки плана больше нет. Нужен `authMode=desktop`: режим ключа показывает
только Coding-модели, а прямой выбор Start с ключом отклоняется. JWT общего
входа Desktop читается заново, без обмена на project token Coding Plan.
Смена модели меняет план следующего обычного хода; уточнение сохраняет активный.

**Provider Usage** показывает остаток/лимит токенов Start, процент расхода и
срок окончания. Если встроенный плагин **Provider usage** отключён, включите
его и откройте его настройки или карточку в боковой панели. bb называет дату временем сброса; подпись Start уточняет, что
это окончание доступа. Каталог и оба окна Usage используют общий balance с
интервалом свежести 60 секунд, в том числе между тредами. Ручная перезагрузка
также использует этот интервал: bb не передаёт её причину в bridge провайдера.
Опроса по таймеру и дополнительного цикла повторов модели нет. Отдельный ресурс
Coding Plan показывает проценты за пять часов/неделю и сообщённые сроки сброса
независимо от Start и выбранной модели. Отсутствие промо, входа и доступной суммы различается.
Успешный balance без промо показывает «No active Start Plan promotion · Coding
Plan is separate» без окон квоты.
Полученный план с будущим началом показывает pending и сообщённое время начала,
не открывая Start-модель заранее. Пока bucket баланса отсутствует, выданный
объём не выдаётся за доступный остаток. Выданный pending или исчерпанный план
подавляет повторную подсказку Claim и обнаружение предложения.
После сообщённого начала полученный план без баланса обозначается как
полученный, с ещё не сообщённым балансом, а не как отсутствие акции. Реальная
доступность модели в этом состоянии ещё требует проверки при активации.
Фоновое извлечение памяти native ZCode тоже расходует токены Start; им управляют
настройка памяти Desktop и существующий fallback.

Переключатель **Check for Start Plan promotions** по умолчанию выключен.
Если он включён и Start отсутствует, каталог читает текущие marketing delivery
Desktop на английском (`en-US`) с общим кэшем 10 минут. В выключенном состоянии
нет запросов маркетинга и подсказок на их основе; balance, уже полученная квота,
каталог Start и Usage работают независимо. Уже отправленный запрос может завершиться.
Чтобы получить квоту по предложению, проверьте право на неё в ZCode Desktop
и примите предложение там. Затем обновите каталог bb. Обнаружение может
занять до минуты. Предложение и выданная квота отображаются отдельно.

Модели Start исчезают при следующем успешном обновлении каталога после
окончания доступа или свежего нулевого доступного остатка. При ошибке bb может
сохранить старый каталог, а при исчезновении модели — выбрать в редакторе
доступную по умолчанию: после промо проверяйте модель перед отправкой.
Прямой запрос недоступного Start-ID плагин отклоняет без подстановки Coding.
Досрочный отзыв может впервые обнаружиться по отказу сервера. После активации
bb может сначала вернуть прежний каталог, обновляя его в фоне; при необходимости
один раз откройте выбор модели заново.

## Совместимость

v0.2.4 проверена на Apple silicon с **bb 0.50.1 и ZCode Desktop 4.0.0
(CLI 0.18.0)**. Проверены вход через Desktop, запрос к GLM-5.4 с файлами и
терминалом, вызов инструмента плагина BB и продолжение той же сессии
в новом процессе.

v0.2.4 может показывать уведомление о совместимости и на этой проверенной связке.

Windows, Linux, Intel macOS, Team Coding Plan, off-peak, BigModel и Browser Use
не поддерживаются. Computer Use и серверный учёт квоты резервного ключа пока
не проверены. Индивидуальные тарифы, кроме Lite, ожидают проверки.

[История релизов](RELEASE_NOTES.md) · [Прошлые проверки и офлайн-проверка совместимости](compat/README.md).

## Границы доверия

Плагины bb исполняются с полным доверием и доступом вашей учётной записи на сервере
и хосте. Перед включением изучите репозиторий и установленный ZCode. Провайдер
запускает CLI через Helper; ZCode управляет запросами к моделям, инструментами
и сетью. Содержимое проекта и запросы могут уходить через ZCode, как при прямом
использовании. Отдельного модельного endpoint или загрузки отчётов плагин не добавляет.

Плагин читает общий вход ZCode; native ZCode может обновлять токены.
Для OAuth-входа bridge получает native project access token в памяти через
API учётной записи Z.ai; credentials и пользовательскую конфигурацию он не пишет.
У сессий bb отдельные данные/история,
они не появляются в Desktop. Плагин записывает привязки сессий, нативные данные,
кэши и диагностику в каталог данных bb. Builtin и personal provider config
выбирает сам ZCode по месту; плагин не хранит их копии. App-server по-прежнему
нужны host account overlay и runtime headers, как в Desktop. Карточки фоновых
задач и checkpoint сохраняют полную native-команду с аргументами. Неподтверждённый
ввод отмечается без повторной отправки и без убийства native-процесса по таймеру
подтверждения; перед повтором нужно выяснить исход.
Исходные личные/проектные настройки и навыки читаются по месту. Нативные плагины
могут запускать hooks и в Desktop, и в bb; включение расширяет круг доверенного
кода. Нативные инструменты имеют полный доступ к настоящему HOME и окружению.

Observer неактивен без явной настройки собственного loopback proxy и сертификата.
Локальные отчёты исключают запросы, содержимое проектов и значения credentials.
Журналы ротируются, но у истории и кэшей хоста нет жёсткого общего лимита.
Не публикуйте каталог данных, сырые журналы, credentials или ссылки авторизации.

## Сообщить о проблеме

В правой панели треда bb выберите **Open new tab → Start terminal** и выполните
`bb zcode-provider-report` (текст), `bb zcode-provider-report --json` или `bb zcode-provider-report --help`.
В этом терминале bb предоставляет CLI; системный PATH настраивать не нужно.
Отчёт **server-local**: он описывает установку и события на сервере bb, а не
удалённый host агента или каталог вызывающего терминала. Личные пути и содержимое
сессий исключены. Наличие файла credentials не доказывает готовность входа;
она не проверяется. Коды выхода: 0 — успех/help, 1 — ошибка сбора,
2 — неверные аргументы; JSON ошибок: `{ok:false,error:{code,message}}`.
При help и неверных аргументах данные не собираются.
Приложите просмотренный вывод к
[GitHub issue](https://github.com/emlevsky777/bb-plugin-zcode/issues), указав шаги,
время/часовой пояс и точную ошибку. Команда ничего не загружает. При нескольких
установках используйте `bb plugin run zcode-provider`. Журналы: `bb plugin logs zcode-provider`.

## Разработка и лицензия

На поддерживаемом host Node: `npm ci`, `npm run typecheck`, `npm test`.
`bb plugin build` создаёт server и host artifacts. Тесты офлайн с синтетическими
fixtures, квоту Coding Plan не расходуют.
