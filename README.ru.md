# ZCode для bb

Запускайте установленный агент ZCode внутри [bb](https://getbb.app) с
индивидуальным Coding Plan Z.ai: файлы, терминал, нативные навыки и команды.
[English](README.md).

Ранний неофициальный плагин, не связанный с Z.ai, ZCode или bb. Плагин не обращается
к Z.ai напрямую: запросы отправляет установленный ZCode. Соответствие использования
условиям Coding Plan — ваша ответственность. Репозиторий пока приватный; нужен доступ.

## Требования и установка

macOS на Apple silicon, bb 0.45.0 или новее, установленный ZCode Desktop, Git
и вход с индивидуальным Coding Plan (проверен Lite). Node и сборщик предоставляет
bb; Python, Homebrew и глобальный npm не нужны.

```sh
bb plugin install 'git:https://github.com/emlevsky777/bb-plugin-zcode.git@v0.1.0-rc.1' --yes
```

bb собирает server и host. ID плагина — `zcode`. Откройте тред, выберите
**ZCode**, модель (GLM-5.3, если доступна), разрешения **Full**, отправьте сообщение.
Разрешения bb определяют доступ инструментов; учитывайте команды и доверие к проекту.

Если нужен вход, скопируйте полную команду Terminal из статуса провайдера и
завершите вход ZCode. Команда `zcode` в PATH не нужна. Следующий запрос обнаружит
изменение входа без перезапуска bb. Переименованные приложения находятся через
Spotlight; резервный поиск — `/Applications` и `~/Applications`. При нескольких
копиях предпочтение отдаётся системному Applications.

Проверка обновлений — `bb plugin outdated`. Тег закреплён: смена тега требует
удаления и новой установки. Удаление сбрасывает настройки, secrets и расписания,
но в bb 0.45.0 файлы и данные плагина остаются; смена тега не сбрасывает эти
сохранённые данные. Для отслеживаемой ветки
или диапазона используйте `bb plugin update zcode --yes`, просмотрев доступную
версию. Перед обновлением или удалением остановите все треды ZCode:

```sh
bb thread stop <thread-id>
bb plugin remove zcode
```

Удаление убирает регистрацию, настройки, secrets и расписания плагина.
bb 0.45.0 сохраняет Git checkout и данные Git-плагинов. При стандартном каталоге
данных bb остаются:

- `~/.bb/plugins/cache/git/github.com/emlevsky777/bb-plugin-zcode/<commit>/`
  — checkout и собранные бандлы установленного commit.
- `~/.bb/plugins/zcode/` — данные плагина, включая `host-data/` и `bridge-data/`.

Для необязательной полной очистки запишите `rootDir` установки из
`bb plugin list --json` **до** удаления. `bb status --json` показывает `dataDir`;
если это не `~/.bb`, замените каталог в путях ниже. Остановите все треды ZCode,
включая фоновую работу, затем выполните `bb plugin remove zcode`.
Только после этого вручную удалите точные оставшиеся каталоги:

```sh
# Замените <commit> на ID checkout, записанный до удаления.
rm -r -- "$HOME/.bb/plugins/cache/git/github.com/emlevsky777/bb-plugin-zcode/<commit>"
rm -r -- "$HOME/.bb/plugins/zcode"
```

Удаляйте checkout, только если его не использует другой установленный плагин;
не удаляйте весь Git-кэш bb. Ручная очистка данных удаляет локальные данные
сессий плагина и кэши, поэтому эти нативные сессии больше нельзя продолжить.
Ни удаление плагина, ни эта очистка не затрагивают вход и историю ZCode Desktop
или историю тредов bb. Сохраните нужные настройки заранее; секретные значения
нельзя переносить в чат или issue.

## Возможности и пределы

- Каталог моделей аккаунта и поддерживаемые уровни рассуждения. Исчезнувшая явно
  выбранная модель или уровень дают ошибку без подмены.
- Продолжение тредов, остановка основной/фоновой работы, сжатие контекста,
  указания во время хода, субагенты при включённой настройке bb.
- Навыки через `/` или `$`, команды через `/` — одна команда на сообщение.
  Для нового резидентного навыка может потребоваться новый тред; обновление меню
  bb может занять около десяти секунд.
- PNG/JPEG/GIF/WebP до 10 MiB, inline-изображения, UTF-8 файлы до 256 KiB.
  PDF, бинарные файлы и удалённые URL изображений отклоняются.
- Личные/проектные инструкции и отдельные навыки. Нативные плагины требуют явного
  включения. Пользовательские MCP и прямые проектные hooks не подключены;
  официальные возможности зависят от поддержки ZCode и bb.

Указания в очереди ZCode могут потеряться при разрыве или продолжении, повтора нет.
Они сохраняют модель, рассуждение и режим входа активного хода; новые настройки
действуют со следующего обычного хода. Отправка с неизвестным исходом автоматически
не повторяется. Перед повтором проверьте тред. Ошибки сервиса показывают причину/код;
проверьте ожидающий повтор bb перед новой отправкой.

Необязательный **Backup Coding Plan key** вводится только в защищённую настройку.
Явно выберите `coding-plan-key`; автоматического перехода с CLI-входа или на
pay-as-you-go API нет. Перед сменой режима остановите всю работу.
Серверный учёт квоты для режима ключа не установлен.

## Совместимость

Статусы описывают наблюдения и не гарантируют будущие версии.

| Конфигурация или возможность | Статус |
| --- | --- |
| macOS arm64; bb 0.45.0, SDK 0.6.15, host Node 24.20.0; ZCode Desktop 3.14.4 / CLI 0.16.9; индивидуальный Lite | Проверено |
| Новые bb/ZCode; индивидуальные тарифы кроме Lite | Ожидается проверка |
| Windows, Linux, Intel macOS; Start Plan, Team Coding Plan, off-peak, BigModel | Не поддерживается |
| Browser Use на проверенной комбинации | Не поддерживается: нативное взаимодействие отклонено |
| Computer Use; серверный учёт квоты резервного ключа | Не установлено |

Непроверенные комбинации показывают уведомление, но запуск и работа могут не
удаться. На Browser/Computer Use рассчитывать нельзя.
[Офлайн-проверка совместимости](compat/README.md) ищет изменения бандлов;
совпадение текста само по себе не доказывает совместимость.

## Границы доверия

Плагины bb исполняются с полным доверием и доступом вашей учётной записи на сервере
и хосте. Перед включением изучите репозиторий и установленный ZCode. Провайдер
запускает CLI через Helper; ZCode управляет запросами к моделям, инструментами
и сетью. Содержимое проекта и запросы могут уходить через ZCode, как при прямом
использовании. Отдельного модельного endpoint или загрузки отчётов плагин не добавляет.

Общий вход ZCode читается без изменений. У сессий bb отдельные данные/история,
они не появляются в Desktop. Плагин записывает привязки сессий, нативные данные,
изолированные представления настроек, кэши и диагностику в каталог данных bb.
Исходные личные/проектные настройки и навыки читаются по месту. Нативные плагины
могут запускать hooks и в Desktop, и в bb; включение расширяет круг доверенного
кода. Проверки после запуска не отменяют уже произошедшие эффекты запуска.

Observer неактивен без явной настройки собственного loopback proxy и сертификата.
Локальные отчёты исключают запросы, содержимое проектов и значения credentials.
Журналы ротируются, но у истории и кэшей хоста нет жёсткого общего лимита.
Не публикуйте каталог данных, сырые журналы, credentials или ссылки авторизации.

## Сообщить о проблеме

Выполните `bb zcode-report` и приложите просмотренный вывод к
[GitHub issue](https://github.com/emlevsky777/bb-plugin-zcode/issues), указав шаги,
время/часовой пояс и точную ошибку. Команда ничего не загружает. При нескольких
установках используйте `bb plugin run zcode`. Журналы: `bb plugin logs zcode`.

## Разработка и лицензия

На поддерживаемом host Node: `npm ci`, `npm run typecheck`, `npm test`.
`bb plugin build` создаёт server и host artifacts. Тесты офлайн с синтетическими
fixtures, квоту Coding Plan не расходуют.
